# Goals to Today 레드팀 사용성 시나리오

이 문서는 기능이 "존재하는지"가 아니라 실제 사용자가 끝까지 목적을 달성할 수 있는지 검증하기 위한 반복 실행용 시나리오다. 테스트 데이터는 `RT-YYYYMMDD-` 접두어를 사용하고, 테스트가 만든 데이터만 정리한다.

## 판정 기준

- `PASS`: 도움 없이 목적을 달성하고, 새로고침 뒤에도 결과가 유지된다.
- `FRICTION`: 목적은 달성하지만 발견성, 피드백, 조작 비용 때문에 실수 가능성이 높다.
- `FAIL`: 목적을 달성하지 못하거나, 잘못된 날짜·상태·사용자 데이터로 저장된다.
- `BLOCKED`: 자격 증명이나 외부 시스템이 없어 실행하지 못했다. 실패와 구분한다.
- `P0`: 개인정보 노출, 계정 간 데이터 오염, 데이터 유실, 잘못된 일정·알림.
- `P1`: 핵심 Todo·일정·계획 흐름이 막히거나 의미와 다르게 동작.
- `P2`: 반복 사용을 방해하는 발견성·접근성·피드백 문제.
- `P3`: 시각적 완성도와 일관성 문제.

모바일 기준은 390×844를 기본으로 하되 320, 768px도 함께 본다. 가로 문서 스크롤은 [WCAG 1.4.10 Reflow](https://www.w3.org/WAI/WCAG21/Understanding/reflow)의 예외에 해당하는 표 내부에서만 허용하고, 페이지 전체가 넓어지면 실패로 본다. 반복 터치 조작은 44×44px을 권장 기준으로, 최소 적합성 판단은 [WCAG 2.5.8 Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)의 24×24px과 간격 예외를 함께 확인한다.

## 공통 테스트 데이터

- 독립 Todo: `RT-YYYYMMDD-세금계산서 보내기`
- 목표 연결 Todo: `RT-YYYYMMDD-장애 대응 문서 초안`
- 독립 일정: `RT-YYYYMMDD-치과 진료`
- 겹침 일정: 위 일정과 같은 시작·종료 시각
- 작업 수: 최소 8개. 6~8번째 항목은 우선순위 후보 검증에 사용한다.
- 계정: 데이터가 있는 A, 완전히 새 계정 B
- 시간대: `Asia/Seoul`; 자정, 일요일 밤, 월요일 아침 경계를 포함한다.

## 핵심 시나리오

### RT-01 신규 사용자가 목표 없이 Todo만 시작한다

- 사용자: 목표 체계보다 오늘 할 일부터 적고 싶은 신규 사용자
- 사전 조건: 계획과 서버 데이터가 없는 새 계정
- 절차:
  1. 로그인한다.
  2. 목표 입력을 건너뛰고 Todo·캘린더 시작 경로를 찾는다.
  3. 독립 Todo를 만들고 완료한 뒤 복원한다.
  4. 새로고침하고 같은 상태인지 확인한다.
- 기대: 목표 생성이 필수가 아니며 Todo 전체 수명주기를 완료할 수 있다.
- 자동화 우선순위: P1

### RT-02 빠른 수집으로 한글 Todo를 한 번만 만든다

- 사용자: 이동 중 한 손으로 메모하는 모바일 사용자
- 절차:
  1. 어느 핵심 화면에서든 빠른 수집을 연다.
  2. 한글 IME 조합 중 Enter를 누른다.
  3. 조합을 끝낸 뒤 Enter를 한 번 누른다.
  4. 연속 Enter와 느린 네트워크에서도 결과를 확인한다.
- 기대: 조합 중에는 제출되지 않고, 완료 후 정확히 한 건만 생성된다. 입력한 위치와 저장 결과가 즉시 보인다.
- 자동화 우선순위: P2

### RT-03 00:00와 23:00에서 독립 일정을 만든다

- 사용자: 야간 근무 또는 자정을 넘기는 일정이 있는 사용자
- 절차:
  1. Today의 00:00 빈 칸을 누른다.
  2. `일정만`을 선택하고 00:00~01:00 일정을 저장한다.
  3. 23:00 빈 칸에서 23:00~24:00 일정을 저장한다.
  4. 새로고침하고 두 일정의 위치와 시간을 확인한다.
- 기대: 모든 시간 칸을 직접 누를 수 있고 종료 24:00을 허용한다.
- 자동화 우선순위: P1

### RT-04 기존 Todo를 일정에 배치하고 Todo는 유지한다

- 절차:
  1. 기존 독립 Todo를 Today 시간표에 배치한다.
  2. 일정 제목과 시간을 수정한다.
  3. `일정에서 삭제`를 실행한다.
  4. Todo 목록에서 원본 Todo가 남아 있는지 확인한다.
- 기대: 일정 삭제 범위가 명확하고 Todo는 삭제되지 않는다.
- 자동화 우선순위: P1

### RT-05 겹치는 일정 저장을 막고 복구 방법을 알려준다

- 절차:
  1. 10:00~11:00 일정을 만든다.
  2. 10:30~11:30 일정을 추가한다.
  3. 오류 뒤 시작 시간을 11:00으로 바꾸고 저장한다.
- 기대: 첫 일정은 보존되고, 오류가 문제 필드 가까이에 표시되며 포커스가 이동한다. 수정 후 한 번에 저장된다.
- 자동화 우선순위: P1

### RT-06 현재 시각과 다음 일정을 즉시 찾는다

- 사용자: 지금 무엇을 해야 하는지만 빠르게 보려는 복귀 사용자
- 절차:
  1. 활성 Todo 8개와 일정 3개가 있는 상태에서 Today를 연다.
  2. 5초 안에 현재 시각, 다음 일정, 일정 추가 버튼을 찾는다.
  3. 모바일에서 스크롤 횟수와 도달 거리를 기록한다.
- 기대: 다음 일정과 현재 시각이 첫 화면 또는 한 번의 명확한 동작으로 노출된다.
- 자동화 우선순위: P2

### RT-07 실제 오늘 요일을 Planner가 강조한다

- 절차:
  1. 화요일부터 일요일 사이에 이번 주 Planner를 연다.
  2. 헤더의 강조 날짜와 운영체제 날짜를 비교한다.
  3. 이전 주·다음 주에서는 오늘 강조가 사라지는지 본다.
- 기대: 현재 주의 실제 오늘만 강조된다.
- 자동화 우선순위: P1

### RT-08 회고의 `다음 주로`가 실제 다음 주에 배치한다

- 절차:
  1. 이번 주 미완료 Todo에서 `다음 주로`를 누른다.
  2. 열린 Planner의 기간과 선택된 날짜를 확인한다.
  3. 저장 후 다음 주로 이동해 한 번만 존재하는지 확인한다.
- 기대: 다음 주 기간이 열리고 `weekOffset=1`에 해당하는 절대 날짜에 저장된다.
- 자동화 우선순위: P1

### RT-09 6번째 이후 Todo도 다음 주 Top 3로 고른다

- 절차:
  1. 활성 Todo를 8개 만든다.
  2. Review의 Top 3 단계에서 7번째 Todo를 찾는다.
  3. 선택하고 회고를 완료한 뒤 Planner에서 확인한다.
- 기대: 모든 활성 Todo를 검색·선택할 수 있다. 임의의 앞 5개 제한이 없다.
- 자동화 우선순위: P1

### RT-10 회고를 미결 상태로 끝내지 않는다

- 절차:
  1. 오래된 결과 2개와 이월 Todo 2개를 만든다.
  2. 결과 하나와 방해 요인 하나, Top 1만 선택한다.
  3. 회고 완료를 시도한다.
- 기대: 남은 필수 결정이 구체적으로 표시되거나, 의도적으로 건너뛰었다는 확인을 받는다.
- 자동화 우선순위: P1

### RT-11 결과 지표의 전체 수명주기를 관리한다

- 절차:
  1. 새 분기 결과를 추가한다.
  2. 단위, 목표값, 현재값, 필요·가용 시간, 근거, 다음 점검일을 수정한다.
  3. 불필요한 결과를 삭제하거나 보관한다.
  4. 결과가 0개인 분기도 저장한다.
- 기대: 기존 결과의 일부 필드만 수정하는 데 그치지 않고 추가·보관·삭제를 명시적으로 지원한다.
- 자동화 우선순위: P1

### RT-12 모바일 Goals가 한 방향으로만 스크롤된다

- 절차:
  1. 390px와 320px에서 Goals를 연다.
  2. 페이지의 `scrollWidth`와 `clientWidth`를 비교한다.
  3. 결과 카드의 현재값·확신·시간·점검·상태를 읽는다.
- 기대: 페이지 전체 가로 스크롤은 없고, 예외적으로 표를 유지한다면 표 컨테이너만 좌우로 움직인다.
- 자동화 우선순위: P1

### RT-13 저장 충돌을 보고 안전하게 병합한다

- 절차:
  1. 기기 A를 오프라인으로 전환해 Todo를 추가한다.
  2. 기기 B에서 분기 방향을 바꾼다.
  3. A를 온라인으로 전환하고 `변경 비교`를 연다.
  4. 항목별 원본을 비교해 병합하고 새로고침한다.
- 기대: 대화상자 본문과 모든 선택지가 보이고, 로컬 Todo와 서버 변경이 모두 한 번씩 남는다. 병합 뒤 추가 편집도 유실되지 않는다.
- 자동화 우선순위: P0

### RT-14 A 계정의 로컬 데이터가 B 계정으로 넘어가지 않는다

- 사전 조건: 같은 브라우저 프로필, 데이터가 있는 A, 서버 데이터가 없는 B
- 절차:
  1. A에서 오프라인 변경을 만들고 로그아웃한다.
  2. B로 로그인한다.
  3. Today·Plans를 확인하고 B에서 작은 편집을 저장한다.
  4. A와 B의 서버 스냅샷을 각각 조회한다.
- 기대: B 화면과 서버에 A 데이터가 한 항목도 없다. ETag·revision은 사용자 간 캐시 판정에 재사용되지 않는다.
- 자동화 우선순위: P0

### RT-15 주 경계를 넘어도 일정 날짜가 바뀌지 않는다

- 절차:
  1. 일요일에 다음 월요일 일정을 만든다.
  2. 시계를 월요일로 넘기고 앱을 재실행한다.
  3. 1주 뒤 같은 요일과 알림도 확인한다.
- 기대: 일정은 지정한 ISO 날짜에 한 번만 나타나고, 완료된 다음 주 일정이 다시 미래로 밀리거나 매주 반복되지 않는다.
- 자동화 우선순위: P0

### RT-16 새 분기 계획은 실행 데이터를 격리한다

- 절차:
  1. 완료 Todo, 시간 기록, 일정, 진행 중 타이머가 있는 계획에서 새 분기 초안을 만든다.
  2. 새 계획을 활성화한다.
  3. Todo·시간표·기록·회고·지표를 확인한다.
- 기대: 사용자가 선택한 방향·결과 템플릿만 재사용하고 과거 Todo, 일정, 시간 기록은 비어 있다. 복사 범위를 생성 전에 보여준다.
- 자동화 우선순위: P1

### RT-17 설정 API 일부 실패를 복구한다

- 절차:
  1. 이용 플랜 API만 403으로 만든다.
  2. Google Calendar와 알림 설정을 확인한다.
  3. 재시도하고 새로고침한다.
- 기대: 성공한 카드는 정상 표시되고 실패한 카드만 오류·원인·재시도를 보여준다. 무한 `불러오는 중`이 남지 않는다.
- 자동화 우선순위: P1

### RT-18 Google Calendar를 실제 데이터로 왕복한다

- 절차:
  1. 연결하고 가져오기 전용 캘린더를 선택한다.
  2. Google 이벤트를 만들고 동기화한다.
  3. 앱의 읽기 전용 일정과 날짜·시간·시간대를 확인한다.
  4. 내보내기 캘린더로 앱 일정을 전송하고 수정·삭제 동기화를 반복한다.
  5. 토큰 만료와 공급자 장애를 주입한다.
- 기대: 양방향 데이터가 중복 없이 수렴하고, 읽기 전용 경계가 명확하며 재인증과 장애 복구 안내가 나온다.
- 자동화 우선순위: P1

### RT-19 실제 OIDC 로그인과 세션 복구

- 절차:
  1. 비로그인 상태로 `/today`에 직접 접근한다.
  2. 로그인·콜백·Today 진입을 마친다.
  3. 새로고침, 브라우저 재시작, 토큰 만료, 로그아웃을 차례로 검증한다.
- 기대: 리다이렉트 루프가 없고, 토큰 만료 시 재인증 안내가 명확하며 로그아웃 후 보호 화면에 접근할 수 없다.
- 자동화 우선순위: P0

### RT-20 모바일·키보드·확대 접근성

- 절차:
  1. 키보드만으로 각 화면, 시간표, 모든 대화상자를 순회한다.
  2. 대화상자 포커스 순환·닫은 뒤 복귀를 확인한다.
  3. 200% 확대와 320px 너비에서 핵심 작업을 완료한다.
  4. 반복 조작 버튼의 크기와 간격을 측정한다.
- 기대: 포커스가 보이고 화면 밖으로 빠지지 않는다. 정보 손실이나 2차원 페이지 스크롤 없이 동일 기능을 쓸 수 있다.
- 자동화 우선순위: P2

### RT-21 Today와 Review가 해당 날짜·주간만 집계한다

- 절차:
  1. 지난주와 어제에 각각 60분 기록과 완료 Todo를 만든다.
  2. 오늘 기록 없이 Today를 열어 실제 시간과 실행률을 확인한다.
  3. 이번 주 30분 기록을 만든 뒤 Review를 연다.
  4. 화면 기간, 실행 시간, 완료 수를 원장 데이터와 대조한다.
- 기대: Today는 오늘 0분, Review는 이번 주 30분만 표시한다. 기간 문구와 집계 경계가 일치한다.
- 자동화 우선순위: P1

### RT-22 모두 완료한 주에도 회고를 정상 종료한다

- 절차:
  1. 이번 주 Todo를 모두 완료해 활성 Todo를 0개로 만든다.
  2. Review의 모든 단계를 진행한다.
  3. 다음 주 Top 작업 없이 회고 완료를 시도한다.
- 기대: `선택할 작업 없음`을 유효한 상태로 인정하거나 새 Todo 생성 경로를 제공하며, 회고를 종료할 수 있다.
- 자동화 우선순위: P1

### RT-23 결과 중단이 연결 Todo의 다음 행동을 결정한다

- 절차:
  1. 한 결과에 미완료 Todo 두 개를 연결한다.
  2. Goals에서 결과를 `중단`한다.
  3. Todo별로 중단·다른 결과 연결·독립 전환을 선택한다.
  4. Today와 Planner에서 실행 가능 상태를 확인한다.
- 기대: 중단된 결과 아래 Todo가 설명 없이 계속 실행 후보로 남지 않으며, 사용자가 명시적으로 처리 범위를 고른다.
- 자동화 우선순위: P1

### RT-24 온보딩이 이미 지난 실행 시각을 제안하지 않는다

- 절차:
  1. 평일 21:00 이후와 토요일 10:00 이후에 신규 온보딩을 각각 시작한다.
  2. 추천 실행 시각을 확인한다.
  3. 사용자 지정 시각과 `나중에 배치`를 선택해 완료한다.
- 기대: 현재보다 과거인 시각은 비활성 또는 다음 날짜로 표시되고, 사용자가 직접 선택하거나 미배치 상태로 진행할 수 있다.
- 자동화 우선순위: P1
