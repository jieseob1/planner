# Nowline 사용성 감사

## 현재 판정 — 2026-09-01 production QA

Nowline은 더 이상 localStorage 전용 프로토타입이 아닙니다. 현재 제품 경로는 OIDC/JWT 인증, 필수 정책 동의, Spring API, MySQL 8.4, ETag 동기화와 충돌 병합까지 연결되어 있습니다. localStorage는 즉시 반응과 오프라인 편집을 위한 캐시이며, 서버가 404를 반환한 신규 계정은 샘플 데이터 없이 onboarding에서 실제 계획을 만듭니다.

- 신규 사용자는 샘플 연간 계획·작업·시간 기록을 받지 않으며 onboarding 입력만 서버에 저장됩니다.
- 계획 초기화는 확인 후 현재 aggregate를 API에서 삭제하고, 실패하면 로컬 사본을 보존합니다.
- 데스크톱 전체 여정과 390×844 모바일 주요 화면, 키보드 건너뛰기/빠른 수집, 200% zoom을 production E2E가 검사합니다.
- 설정의 개인정보·약관 링크를 포함해 모바일에서 보이는 상호작용 대상은 44 CSS px 제품 기준으로 검사합니다.
- 실제 OIDC 공급자, Google 계정, Web Push/APNs/FCM, VoiceOver/TalkBack과 서명 앱은 외부 자격 증명·실기기가 필요한 별도 승인 항목입니다.

최신 화면별 증거와 남은 한계는 [Production UX audit](./PRODUCTION_UX_AUDIT.md), 기능별 구현·QA 상태는 [Feature QA matrix](./FEATURE_QA_MATRIX.md)를 기준으로 합니다.

## 역사 기록 — 백엔드 연결 전 프론트엔드 감사

아래 내용은 초기 localStorage 프로토타입에서 발견한 U-01~U-14와 당시 재검증 기록을 보존한 것입니다. 현재 제품 상태를 설명하는 문서가 아니며, 현재 판정과 충돌할 때는 위 production QA와 기능 매트릭스를 우선합니다.

감사일: 2026-08-31  
대상: `http://localhost:4173` 및 동일 앱의 `127.0.0.1` origin  
범위: Today, Planner, Goals, Review, Onboarding의 데스크톱(1440×900)·모바일(390×844), 키보드, 상태 피드백, 오류 예방, 레이블, 핵심 작업 완료

> **당시 제품 단계 해석:** Spring API·DB·로그인·서버 동기화가 없던 프론트엔드 프로토타입을 대상으로 했습니다. 아래의 `localStorage` 데모 설명은 2026-08-31 시점 기록입니다.

## 결론

핵심 실행 흐름은 로컬 데모 상태에서 동작하고 전체 문서 폭의 모바일 overflow나 브라우저 오류도 없었다. 다만 **로컬 저장이 클라우드 동기화처럼 보이는 문제**, **활성 상태지만 반응이 없는 주요 버튼**, **일정 충돌과 전체 초기화에 대한 오류 예방 부재**, **Review 값이 Goals에 반영되지 않는 프론트 상태 단절**은 백엔드 유무와 별개로 프로토타입 사용성을 떨어뜨렸다.

- **P0:** 관찰된 항목 없음. 감사 중 충돌·오류·콘솔 예외로 앱이 멈추는 현상은 없었다.
- **P1:** 출시 전에 고쳐야 할 신뢰·핵심 흐름 문제 8개.
- **P2:** 접근성과 발견성을 높일 개선 6개.

우선순위 정의: P0는 핵심 흐름 중단 또는 복구 불가능한 광범위 손실, P1은 핵심 흐름·데이터 신뢰를 크게 훼손, P2는 우회가 가능하지만 반복 사용이나 접근성을 떨어뜨리는 문제다.

## 정상 동작으로 확인한 부분

아래는 **관찰 결과**이며 개선 제안이 아니다.

- Today: 작업 시작→일시 정지→종료 모달→완료/계속 기록 흐름이 동작한다. 종료 모달은 최초 초점, `Escape`, `Shift+Tab`/`Tab` 경계 순환을 제공한다.
- Today 빠른 수집: 다른 화면의 `빠른 수집`을 누르면 Today로 이동해 입력창에 초점이 가며, 제출 후 `수집함에 넣었어요.` 상태가 표시된다.
- Planner: 작업 선택→요일·시간·예상 시간 선택→배치가 동작하고, 블록·용량·미배치 개수 갱신 및 `…에 배치했어요.` 상태 피드백이 확인됐다.
- Goals: 유지/축소/기한 연장/중단 선택이 `aria-pressed`와 결정 개수에 즉시 반영되고 다시 바꿀 수 있다.
- Review: 지표 선택, 방해 요인, Top 3, 완료의 4단계 가드와 완료 화면이 동작한다.
- Onboarding: 입력란 `Enter`로 1→2→3단계 진행, 시간 선택, 첫 실행 생성, Today 이동까지 완료됐다.
- 키보드: 본문 건너뛰기 링크, 의미 있는 네이티브 버튼·링크·입력 레이블, `:focus-visible` 스타일이 있다. 모달 `Escape` 닫기와 양 끝 초점 순환을 실제 확인했다.
- 모바일: 390×844에서 Today, Planner, Goals, Review, Onboarding 모두 문서 전체 폭은 390px로 유지됐다. 콘솔 warning/error는 데스크톱·모바일 모두 0건이었다.

## P1 발견 사항

### U-01 · 저장 상태가 서버 동기화로 오인된다

- **관찰:** 모든 화면의 `SaveStatus`가 `동기화 중`, `동기화됨`, `동기화 실패`라고 표시한다. 실제 구현은 `PlannerProvider`가 180ms 뒤 브라우저 `localStorage`에만 기록하며 서버 응답이나 계정 동기화는 없다. Review에는 같은 상태가 상단 바, 헤더, 하단 안내에 최대 3번 반복된다.
- **사용자 결과:** 다른 기기나 계정에도 백업됐다고 믿고 브라우저 데이터 삭제·기기 변경 후 계획을 잃을 수 있다.
- **수용 조건:** 백엔드가 없는 현재 버전은 `이 기기에 저장 중`/`이 기기에 저장됨`/`기기 저장 실패`로 표시하고 온라인 여부를 동기화 성공처럼 사용하지 않는다. 한 화면의 대표 상태는 한 번만 노출한다. 향후 서버 연결 시 실제 서버 확인 응답 뒤에만 `동기화됨`을 표시한다.

### U-02 · 데모 초기화가 확인이나 복구 없이 전체 로컬 계획을 지운다

- **관찰:** 상단의 아이콘 버튼 `데모 초기화`는 `resetDemo()`를 즉시 실행해 저장 키를 삭제하고 데모 스냅샷으로 교체한다. 확인, 영향 범위 안내, 실행 취소가 없다. 데이터 삭제이므로 감사 중 실제 클릭은 수행하지 않고 코드를 대조했다.
- **사용자 결과:** 작은 아이콘을 잘못 눌러 목표, 작업, 시간 기록, Review 결정을 한 번에 잃을 수 있다.
- **수용 조건:** 클릭 시 `이 기기의 모든 Nowline 계획과 기록을 지웁니다` 확인 모달을 띄우고 취소를 기본 초점으로 둔다. 초기화는 명시적인 두 번째 동작 뒤에만 실행하며 가능한 경우 직전 스냅샷 복구 또는 실행 취소를 제공한다.

### U-03 · Planner의 주 이동 버튼이 활성 상태지만 아무 동작도 하지 않는다

- **관찰:** `이전 주`, `이번 주`, `다음 주`를 눌러도 URL, `8월 31일–9월 6일` 헤더, 표 데이터가 모두 그대로다. 세 버튼에는 이벤트 핸들러가 없다.
- **사용자 결과:** 다음 주 계획을 만들거나 과거 주를 검토할 수 없고, Review의 `다음 주 시간 배치` 약속도 이행할 수 없다.
- **수용 조건:** 각 버튼이 표시 기간과 해당 기간 데이터를 변경하고 새로고침 후 유지한다. 아직 다중 주를 지원하지 않으면 버튼을 제거하거나 비활성화하고 `현재 주만 지원` 이유를 인접 텍스트로 제공한다.

### U-04 · 작업·계획 편집 버튼이 활성 상태지만 아무 동작도 하지 않는다

- **관찰:** Planner의 `다음 행동 추가`와 Goals의 `계획 편집`을 클릭해도 URL, 다이얼로그, 상태 문구, 데이터가 변하지 않는다. 두 버튼 모두 핸들러가 없다.
- **사용자 결과:** 데모 데이터 밖의 다음 행동을 정식으로 만들거나 1년·분기 계획을 수정할 수 없어 개인 계획 관리 도구의 핵심 목적을 달성하지 못한다.
- **수용 조건:** `다음 행동 추가`는 제목·예상 시간·연결 결과를 입력하고 생성 직후 미배치 목록에 보여준다. `계획 편집`은 연간 방향, 분기 결과, 목표값, 기한, 필요/가용 시간을 편집하고 저장 후 Goals·Planner에 일관되게 반영한다. 미구현 상태로 배포한다면 두 컨트롤을 제거하거나 이유와 예정 범위를 표시한 비활성 상태로 바꾼다.

### U-05 · 이월 작업의 빠른 조치가 해당 작업을 조작하지 않는다

- **관찰:** Today의 `나누기`와 `날짜 변경`은 둘 다 일반 `/planner`로, `중단`은 일반 `/goals`로만 이동한다. `나누기`를 실제 클릭한 뒤 선택된 작업, 편집 시트, 안내 상태가 하나도 없었다.
- **사용자 결과:** 경고가 제안한 결정을 수행할 수 없고 사용자는 이동한 화면에서 같은 작업을 다시 찾아야 한다.
- **수용 조건:** 세 조치는 `장애 복구 흐름 다이어그램 작성`의 식별자를 유지한다. 나누기는 하위 행동 편집, 날짜 변경은 해당 작업 배치 시트, 중단은 해당 결과의 결정 확인을 바로 연다. 단순 이동만 제공한다면 버튼 문구를 `Planner에서 찾기`처럼 실제 결과에 맞춘다.

### U-06 · 일정 겹침을 경고하지 않고 같은 시간에 이중 배치한다

- **관찰:** Onboarding에서 기본 `오늘 저녁 19:30 · 40분`으로 첫 실행을 만들자 기존 `19:30 · 1시간 30분` 블록과 겹친 채 둘 다 Today 타임라인에 나타났다. `scheduleTask`와 `finishOnboarding`에는 기존 내부/외부 블록 충돌 검사가 없다.
- **사용자 결과:** 동시에 실행할 수 없는 계획이 정상 계획처럼 저장되어 시간표와 실행 가능성을 신뢰하기 어렵다.
- **수용 조건:** 저장 전에 같은 요일의 시간 구간 교집합을 검사한다. 충돌 시 기존 일정명과 시간을 보여주고 `다른 시간 선택`을 기본 동작으로 제공하며, 의도적 겹침은 명시적 확인 뒤에만 허용한다. 저장 후 테스트 데이터에는 확인 없는 겹친 블록이 0개여야 한다.

### U-07 · Review의 지표 반영이 Goals 결과에 반영되지 않는다

- **관찰:** Review의 `현재 확인된 수익`에 `24`를 입력하고 `반영`한 뒤 Goals로 이동해도 `사이드 수익 월 80만원`은 계속 `data unavailable`, `12일 지연`, `수치 갱신 필요`였다. 구현은 문자열을 `review.metricDraft`에만 저장하며 Outcome의 현재값·갱신 시점·근거를 바꾸지 않는다. 숫자가 아닌 임의 문자열도 비어 있지 않으면 반영할 수 있다.
- **사용자 결과:** 사용자는 수치를 갱신했다고 믿지만 판단 큐와 진척률은 낡은 값을 유지해 잘못된 주간 결정을 내릴 수 있다.
- **수용 조건:** 유효한 0 이상의 숫자만 반영하고 단위와 오류 문구를 제공한다. 반영 시 연결된 Outcome의 `current`, 갱신 시점, 근거/상태를 한 트랜잭션으로 갱신하며 Goals에서 즉시 `24 / 80만원`, 새 진척률과 최신 갱신 상태가 보여야 한다. `변화 없음`은 숫자 필드 값이 아니라 별도 점검 결과로 저장한다.

### U-08 · Review의 다음 주 Top 3가 실제 다음 주 계획으로 이어지지 않는다

- **관찰:** Review 완료는 `selectedTopTaskIds`와 완료 시각만 저장한다. Planner는 이 선택을 읽거나 강조하지 않고 고정된 현재 주만 표시한다. 완료 화면의 `다음 주 시간 배치`는 동일한 `/planner`로 이동한다.
- **사용자 결과:** 4단계 회고를 마쳐도 선택한 실행이 다음 주 큐·시간표로 전달되지 않아 다시 찾아 배치해야 한다.
- **수용 조건:** Review 완료 시 대상 주를 명시하고 선택 Top 3를 그 주의 우선 미배치 목록으로 전달한다. 링크는 실제 다음 주 기간을 연 Planner로 이동하며 선택 항목을 상단에 표시한다. 재진입·새로고침 후에도 주와 우선순위가 유지돼야 한다.

## P2 발견 사항

### U-09 · 일부 모바일 터치 대상이 44×44 CSS px보다 작다

- **관찰:** 390×844에서 Planner `이전 주`/`다음 주`는 각각 36×44, Review 수치 입력은 289×43, `변화 없음으로 기록`은 113×38, Onboarding 예시 칩은 108×34·106×34·98×34로 측정됐다.
- **사용자 결과:** 엄지 조작과 운동·시각 제약이 있는 사용자의 오탭 가능성이 커진다.
- **수용 조건:** 모든 모바일 상호작용 요소의 실제 hit area를 양쪽 모두 최소 44 CSS px로 만든다. 시각 크기를 유지한다면 투명 패딩/의사 요소를 포함한 클릭 영역을 측정해 44×44 이상임을 보장한다.

### U-10 · 모바일 표의 가로 스크롤과 숨은 열을 발견하기 어렵다

- **관찰:** 문서 자체 overflow는 없지만 Planner 표는 보이는 354px 안에서 1090px, Goals 표는 390px 안에서 890px을 수평 스크롤한다. 첫 화면에는 좌우 이동 안내나 현재 스크롤 위치 신호가 없고 Goals에서는 시간·점검·상태 열이 화면 밖에 있다.
- **사용자 결과:** 사용자가 숨은 열의 존재를 모르거나 목표 상태를 보기 위해 반복해서 가로·세로 이동해야 한다.
- **수용 조건:** 모바일에서 핵심 행을 카드로 재배치하거나, 고정된 첫 열과 명확한 `좌우로 밀어 상태 확인` 안내·가장자리 그라데이션·스크롤 위치 신호를 제공한다. 키보드 초점 항목도 자동으로 보이는 영역에 들어와야 한다.

### U-11 · 작은 보조 텍스트의 대비가 부족하다

- **관찰:** Onboarding의 `예시`는 10.4px, `#8b93a1` on `#f5f6f8`로 계산 대비가 약 2.86:1이다. 같은 `--text-3` 토큰이 여러 작은 보조 레이블에 사용된다.
- **사용자 결과:** 저시력 사용자뿐 아니라 밝은 야외 모바일 환경에서도 안내를 읽기 어렵다.
- **수용 조건:** 의미 있는 일반 텍스트는 실제 배경 대비 4.5:1 이상, 큰 텍스트는 3:1 이상을 충족한다. `--text-3`를 일괄 변경하기 전에 장식과 의미 텍스트를 구분하고 대표 화면에서 자동 대비 검사를 통과한다.

### U-12 · Goals의 상태 언어가 한국어 흐름과 섞인다

- **관찰:** 한국어 화면에서 결과값 없음이 시각 텍스트와 `aria-valuetext` 모두 `data unavailable`로 표시되고 `OUTCOME`, `CURRENT` 같은 영어 레이블도 함께 사용된다.
- **사용자 결과:** 특히 값이 없는 상태가 오류인지 미입력인지 즉시 이해하기 어렵고 스크린리더 경험도 일관되지 않다.
- **수용 조건:** 데이터 없음은 `측정값 없음` 또는 `아직 입력하지 않음`처럼 원인에 맞는 한국어로 통일하고 접근성 텍스트도 동일하게 변경한다. 제품 고유 용어가 아닌 상태·조작 문구는 한 화면에서 한 언어를 사용한다.

### U-13 · 수동 시간 추가가 되돌릴 수 없고 완료 피드백이 없다

- **관찰:** Today의 `25분 추가`와 상세 영역 `시간 추가`는 즉시 TimeEntry를 만들지만 어떤 항목에 얼마가 추가됐는지 토스트가 없고, 기록 목록·수정·삭제/실행 취소 진입점도 없다.
- **사용자 결과:** 중복 탭이나 잘못 선택한 시간으로 실행률이 틀려도 사용자가 복구할 수 없다.
- **수용 조건:** 추가 직후 작업명과 시간을 포함한 상태 메시지와 `실행 취소`를 제공하고, 시간 기록 목록에서 수동 기록을 수정·삭제할 수 있게 한다. 연속 탭 방지 또는 멱등 처리도 검증한다.

### U-14 · 키보드 빠른 수집 제출은 실제 기기 확인이 필요하다

- **관찰:** 빠른 수집 입력은 올바른 `<form>`과 submit 버튼을 사용한다. 그러나 감사 자동화의 `Enter` 키 입력은 값을 제출하지 않았고 버튼 클릭은 정상 제출·초기화·상태 피드백을 만들었다. 같은 자동화에서 Onboarding 입력의 `Enter` 진행은 정상 동작했다.
- **사용자 결과:** 실제 브라우저에서도 재현된다면 키보드 사용자는 포인터로 제출 버튼을 찾아야 한다. 다만 자동화 입력 방식의 한계일 가능성을 배제하지 못했다.
- **수용 조건:** macOS/Windows 실제 키보드와 iOS/Android 소프트 키보드에서 입력 후 Enter/완료 키가 정확히 한 번 제출되는 것을 검증한다. 실패가 재현되면 입력 `onKeyDown` 또는 명시적 submit 경로를 추가하고 회귀 테스트를 둔다.

## 확인 한계

- 실제 iOS/Android 네이티브 WebView, 화면 회전, safe-area, 스크린리더(VoiceOver/TalkBack), 물리 키보드 Enter는 이번 브라우저 감사 범위 밖이다.
- 오프라인 전환과 저장 용량 초과는 코드를 검토했지만 실제 네트워크/스토리지 오류를 주입하지 않았다.
- `데모 초기화`는 복구 불가능한 로컬 삭제 동작이므로 실제 클릭하지 않았다.
- 데스크톱·모바일 감사에 사용한 두 origin의 데이터는 서로 독립이며, 실사용 계정 데이터는 사용하지 않았다.
