# 목표 연결 구조와 월간 일정표

2026-09-08 제품 개선. 기존에 저장된 목표·할 일·일정 데이터를 그대로 사용하며, 데이터 이관이나 새로운 필수 목표는 없습니다.

## 목표를 작은 결과로 나누기

1. **목표 → 기간별 목표**에서 확인할 일·주·월·분기·연간 기간을 고릅니다.
2. 목표 옆 **하위 목표**를 누르면 상위 목표가 연결된 편집기가 열립니다. 기본 추천 기간은 연간→분기→월→주→일입니다. 기간과 상위 목표 연결은 자유롭게 바꿀 수 있습니다.
3. 제목을 적고 **목표 저장**을 누릅니다. 수치와 할 일 연결은 필수가 아닙니다.
4. 목표 제목을 누르면 수정합니다. 왼쪽 화살표로 하위 목표를 접거나 펼칩니다. 선택 기간의 목표와 연결된 상위·하위 목표를 함께 표시합니다. 관계없는 다른 기간의 형제 목표는 표시하지 않습니다.

상위·하위 목표는 **각각 따로 측정**합니다. 하위 목표 완료, 할 일 완료, 집중 시간은 상위 목표 달성률을 자동으로 올리지 않습니다. 순환 관계가 생기지 않도록 자기 자신과 하위 목표는 상위 목표 후보에서 제외합니다. 서버의 관계 검증도 유지됩니다.

하위 목표 초안은 계정과 상위 목표별로 구분해 보관합니다. 취소해도 다른 목표의 초안으로 섞이지 않습니다. 목표 삭제는 기존 원칙처럼 연결된 할 일·일정을 삭제하지 않으며, 하위 목표가 있는 부모는 먼저 자식의 연결을 해제해야 합니다.

## 월간 일정 사용하기

**Planner → 월간**을 누릅니다. 기존 **주간** 보기와 함께 사용할 수 있습니다.

- 날짜를 선택하면 아래에 그날의 모든 일정을 시간순으로 보여줍니다.
- **일정 추가**는 목표·할 일 없이 독립 일정을 만듭니다. 편집기에서 **새 할 일**이나 **기존 할 일**로 바꿀 수도 있습니다.
- 내 할 일 목록에서 제목을 누르면 월간 달력에서 선택한 날짜에 배치합니다.
- 일정 제목을 누르면 날짜·제목·시간을 수정하거나 삭제할 수 있습니다. 날짜 입력으로 다른 주·월·연도로 이동할 수 있습니다.
- 외부 캘린더 일정은 읽기 전용입니다. 원본 캘린더에서 수정한 후 동기화합니다.
- 모바일에서는 작은 날짜 칸에 제목을 억지로 넣지 않고 **일정 개수 + 선택 날짜 목록**으로 확인합니다. 날짜 버튼과 하단 추가 버튼만으로 모든 일정을 확인하고 편집할 수 있습니다.
- 키보드 방향키로 하루/한 주, Home·End로 주의 첫날/마지막 날을 선택합니다. Enter/Space로 버튼을 실행합니다.

## 내부 동작과 보존 규칙

| 구분 | 원본·저장 경로 | 주의점 |
|---|---|---|
| 목표 연결 | 기존 `PeriodGoal.parentId` → `PeriodProvider` 저장 | 달성률 합산 없음, 낙관적 잠금과 오류 시 초안 보존 유지 |
| 월간 일정 | 현재 활성 계획의 `TimeBlock.date` → `PlannerProvider.saveTimeBlock` | 보관된 다른 계획의 일정까지 섞지 않음 |
| 날짜 | 날짜 문자열로 월/주 계산, 계정 시간대로 오늘 판정 | 브라우저의 UTC 변환으로 날짜가 하루 밀리지 않음 |
| 충돌 | 저장할 **실제 날짜**의 블록만 비교 | 다른 주의 같은 요일·시간은 충돌로 간주하지 않음 |
| 편집 호환성 | 월간 편집기만 절대 날짜 입력, 기존 주간은 요일 선택 유지 | 자정 00:00·하루 끝 24:00 지원 유지 |
| 날짜 범위 | 현재 주 기준 -520~+520주 | 기존 API의 `weekOffset` 검증 범위를 벗어난 저장 방지 |

## 검증과 한계

집중 회귀 테스트는 하위 목표 생성·연결·다시 읽기·초안 분리·독립 진행률·접기·순환 데이터 방어, 윤년·연말·6주짜리 달·오늘 시간대, 월간 일정 추가·이동·삭제·충돌·주간 호환을 검사합니다. React 검토에서는 날짜별 색인, 파생 상태, 접근 가능한 네이티브 버튼, 불필요한 라이브러리 추가 방지를 확인했습니다.

테스트의 저장 응답은 모의 서버/Provider입니다. 실제 배포·브라우저·계정 저장 확인은 릴리스 통합 QA에서 별도로 검증해야 합니다. 모바일 분기는 DOM 동작과 CSS로 점검했으며 실제 기기 터치/화면 검증을 자동 테스트 결과와 동일시하지 않습니다. Google 실계정 동기화·기기 푸시, 다른 계획의 일정 통합, 반복 일정 작성, 여러 날에 걸친 일정은 이 UI 개선의 검증 범위가 아닙니다.
