# 기간별 목표 · 오늘 실행 · 돌아보기

상태: 2026-09-07 구현, 격리된 Spring/MySQL 실제 Chrome QA 및 전체 production E2E 통과. main CI와 Mac mini 배포는 해당 커밋의 Actions와 public version.json으로 별도 확인한다. 과거 production 저장 오류의 근본 원인 해결 문서가 아니다.

## 선택한 방향

시안 2의 Today 중심 흐름에 시안 1의 기간별 목표 목록, 시안 3의 회고 요약을 결합했다. 기존 인디고/흰색 UI와 달력 직접 조작을 유지하고 주요 메뉴는 오늘·일정·목표·돌아보기 네 개로 정리한다. 모든 기간의 목표를 순서대로 작성하는 절차는 없다.

## 사용 방법

1. 목표에서 일/주/월/분기/연간과 기준 날짜를 선택하고 `목표 추가`를 누른다. 제목만 적어도 완료형 목표를 저장할 수 있다.
2. 목표 행을 누르면 제목·기간·측정법·완료 여부를 수정할 수 있다. 수치형은 기준값·현재값·목표값·단위를 설정한다. 목표값이 기준값보다 작으면 감소 목표다.
3. 상위 목표·할 일 연결·메모는 펼쳐서 설정한다. 기존 할 일을 고르거나 같은 제목으로 새 독립 할 일을 만든다. 생성한 할 일의 기존 플래너 저장이 끝나야 목표에 연결하여 서버 저장할 수 있다. 동일 제목의 기존 할 일이 있으면 재사용한다.
4. Today에서는 날짜와 겹치는 목표를 확인하고 기존 24시간 시간표를 사용한다. `하루 마무리`에서 세 줄과 자유 메모를 남긴다. 모든 글 항목은 선택이고 목표 수치 갱신은 필수가 아니다.
5. 돌아보기는 지난주로 시작한다. 기간을 이동해 기록을 남기거나 지난 기록을 다시 열어 수정한다. `회고 쓰기`를 누르면 긴 목표 목록을 지나 입력란으로 바로 이동한다. `완료`는 작성 상태이며 이후 수정할 수 있다.
6. 목표 삭제는 연결 Todo·일정을 삭제하지 않는다. 하위 목표가 있으면 상위 연결을 먼저 해제한다. 회고 삭제는 선택 기간의 회고만 지우며 다시 작성할 수 있다.

## 도메인과 저장

| 데이터 | 소유/수명 | 연결 |
| --- | --- | --- |
| PeriodGoal | 계정 단위. 활성 분기 계획 교체와 독립 | 선택 parentId, 선택 taskIds. 순환·다른 계정 참조 거절 |
| PeriodReview | 계정+기간 단위+시작일로 식별 | 최초 저장 시 겹치는 목표 측정값을 goalCheckpoints에 함께 보관 |
| period_document | 문서 현재 revision, JSON body, 삭제 상태 | app_user FK, 계정 삭제 시 cascade |
| period_document_history | 변경마다 이전 결과도 유지하는 append-only 버전 기록 | user+mutationId unique, 동일 요청 재시도는 기존 응답 재생 |
| Task.completedAt | 체크 완료 시각. 과거 데이터는 null 유지 | 이름 수정으로 바뀌지 않음. 완료 취소 시 제거, 재완료 시 새 시각 |
| 기존 Outcome/Plan/ReviewState | 기존 모델과 이력 보존 | 기존 분기 관리·주간 지표/이월 화면을 별도 URL로 유지 |

`GET /api/v1/period-documents`는 현재 계정 문서를 조회한다. `PUT`은 `expectedRevision`, `mutationId`, `goal` 또는 `review` 하나, `deleted`를 받는다. 신규 문서는 expectedRevision=0, 수정은 조회한 문서 revision이 필요하다. 토큰에서 계정을 결정하고 클라이언트가 userId를 지정하지 않는다. app_user 행 잠금+트랜잭션이 여러 Spring 인스턴스에서도 적용되므로 같은 revision의 동시 요청 중 하나만 저장된다. 기존 `/api/v1/planner`의 계정 결합 strong ETag 검사는 그대로다.

계정 내보내기에는 두 신규 테이블이 포함된다. MySQL 전체 DB 백업은 신규 테이블과 completed_at도 포함한다. 신규 Flyway V12 적용 후 backend/frontend를 함께 배포해야 하며, 운영 DB에서 과거 migration 파일을 수정하거나 체크섬을 임의 보정하지 않는다.

## 집계 정책

- 일/주/월/분기/연간의 시작/끝은 달력 날짜로 계산한다. 주 시작은 월요일이며 연말을 가로지르는 주, 윤년을 지원한다. 시각→날짜 변환은 계정 시간대를 쓴다.
- 완료한 일은 현재 완료 상태이며 completedAt이 선택 기간에 속하는 항목이다. 타이머는 필요 없다. 완료 취소하면 제외, 재완료하면 마지막 완료일에 집계한다. 과거 완료 날짜는 추정하지 않고 미집계 개수를 안내한다.
- 계획 시간은 해당 날짜의 내부 시간 블록 구간 합집합이다. 겹침은 중복 계산하지 않고 외부 일정은 제외한다.
- 기록 시간은 TimeEntry.observedAt 날짜에 durationSeconds를 귀속한다. 기존 구조로는 자정을 넘긴 실제 실행 구간을 정확히 분할할 수 없으므로 그 제한을 화면에 표시한다.
- 현재 계획과 종료·보관 계획의 스냅샷에서 실행 내용을 읽고 안정적인 항목 ID로 중복 제거한다. 같은 ID의 현재 계획 값이 우선이다. 삭제/수정한 실행 데이터는 현재 보관된 스냅샷 기준으로 다시 계산하므로 회고 당시 실행 요약을 불변 감사 수치라고 주장하지 않는다.
- 목표 진척은 완료 여부 또는 `(현재-기준)/(목표-기준)`이다. 미측정은 0%로 단정하지 않는다. 시간·할 일 완료 개수·부모/자식 진척을 임의 합산하지 않는다.
- 회고의 목표 수치는 최초 저장 시점 checkpoint다. 회고 글을 고쳐도 과거 checkpoint가 오늘 목표 수치로 바뀌지 않는다.

## 저장 실패와 데이터 보존

입력 초안은 계정+문서 키에 revision 및 mutationId와 함께 저장한다. 새 계정으로 넘기거나 자동 업로드하지 않는다. 서버 412에서는 입력을 유지하고 최신 서버 문서와 비교한다. 사용자가 `내 입력 선택` 후 다시 저장해야 revision을 바꾼다. 기존 플래너 충돌에서 어느 쪽 데이터를 유지할지는 자동 선택하지 않는다. 기기 저장 실패 시 탭을 닫지 말라는 안내가 나오며, 저장 실패를 성공으로 표시하지 않는다.

날짜·계정이 없는 이전 기기 메모는 키를 그대로 보존한다. 사용자가 `이전 기기 메모 확인`을 눌렀을 때 읽기 전용으로 보여주며, 새 회고로 자동 귀속하지 않는다.
