# 작은 베타에서 제품을 개선하는 방법

이 문서는 **실행 가능한 모집·운영 초안**입니다. 사용자 초대, 커뮤니티 게시, 광고 집행, 실제 인터뷰·재방문 측정은 아직 수행하지 않았습니다. 예시 숫자는 운영 목표이며 실제 성과가 아닙니다.

## 누구에게 무엇을 말할까

- 첫 대상 가설: 일·공부·개인 프로젝트를 병행하며 Todo와 캘린더를 따로 관리하는 사람. 나이·성별이 아닌 실제 사용 상황으로 모집합니다.
- 첫 3초 메시지: **큰 목표가 없어도, 오늘 할 일부터 시작하세요.**
- 보조 설명: 할 일을 작은 단계로 나누고 시간표에 배치한 다음, 하루·주·월을 돌아봅니다. 필요해지면 연간·분기 목표와 연결합니다.
- 행동 하나: 무료 웹 베타에서 오늘 할 일 하나를 적어 보기.
- 가장 큰 장벽: 기존 도구에서 모두 옮겨야 한다는 부담. 처음에는 하루만 병행해 보도록 안내합니다.
- 증거: 실제 Todo·하위 할 일·날짜 이동·목표 트리 화면과 검증된 사용 시연. 가짜 후기·가입자 수·생산성 향상 수치는 사용하지 않습니다.

구글 실계정 연동, 네이티브 15분 전 알림, 실제 AI 보고서, 스토어 앱은 별도 설정·검증 관문을 통과하기 전까지 **준비 중**으로 표현합니다. 베타는 자동 유료 전환되지 않습니다.

## 모집과 학습 순서

| 시점 | 수행할 일 | 남길 증거 |
| --- | --- | --- |
| 초대 전 | 로그인·저장·수정·삭제, 백업 복원, 장애 연락 체계 확인 | 릴리스 SHA, QA 결과, 담당자와 대응 시간 |
| 1주차 | 운영자가 아는 5명에게 동의받아 개별 초대, 15분 사용 관찰 | 어디에서 멈췄는지·도움 없이 성공했는지·걸린 시간 |
| 2주차 | 반복 불편 상위 1~2개 수정 후 최대 20명으로 확대 | 수정 전후 동일 시나리오 결과, 재방문 이유 |
| 이후 | 관련 커뮤니티의 홍보 규칙 확인 후 제작기·짧은 시연 게시 | 채널별 방문→가입→첫 사용과 피드백 |

현재 공개 가입이 가능한 상태와 별개로 **테스터 수를 기술적으로 제한하는 초대 전용 게이트는 없습니다**. 엄격한 제한 베타가 필요하면 초대 코드/허용 목록을 먼저 추가하세요. 승인 없는 대량 DM, 연락처 수집, 커뮤니티 자동 게시는 하지 않습니다. 유료 광고는 첫 사용과 재방문이 확인된 후 별도 예산을 정합니다.

### 전달 문구 초안

>
> 시작: https://goalstotoday.com · 피드백: 설정 → 문제 신고·개선 제안

게시 전 제품 상태, 지원 가능 시간, 해당 커뮤니티 규칙을 다시 확인합니다. 공개 GitHub 문의에는 개인 일정·이메일·토큰·스크린샷 원본을 올리지 않도록 안내합니다. 비공개 지원 이메일/폼은 운영자가 수신처를 정한 뒤 연결합니다.

## 실제 사용자 관찰 시나리오

1. 도움 없이 가입하고 목표 없이 할 일 하나 만들기.
2. 하위 작업 두 개를 Enter로 추가하고 하나만 완료하기.
3. 오늘 시간표에 배치하고 다음 달로 옮겼다가 다시 수정하기.
4. 새로고침·재로그인 후 입력이 유지되는지 확인하기.
5. 하루 회고를 적고 지난주 돌아보기에서 계획 시간과 기록 시간의 차이를 설명해 보기.
6. 목표를 두 단계로 나누되 하위 목표 완료가 상위 목표에 자동 반영되는지 직접 판단해 보기.
7. 의도적으로 찾기 어려웠던 기능을 설정에서 신고해 보기. 실제 공개 게시 없이 초안까지만 확인합니다.

관찰자는 답을 먼저 알려주지 않고, 마지막 실제 사용 사례와 막힌 지점을 묻습니다. 녹화·화면 공유는 사전 동의하고, 기록 본문 대신 단계·성공 여부·소요 시간 위주로 보관합니다.

초기에는 광고보다 직접 사용 관찰과 재방문 확인을 우선한다는 [YC 초기 성장 Q&A](https://www.ycombinator.com/blog/growth-ama-with-yc-partner-gustaf-alstromer)를 참고했습니다. 위 5명/20명과 일정은 이 제품에 맞춘 운영 제안이지 해당 자료의 보장 수치가 아닙니다.

## 매일·매주 볼 것

- 매일: 로그인 실패, 저장 4xx/5xx, 작업 실패, Grafana 메모리, 백업 신선도, 긴급 문의. 데이터 유실·다른 계정 데이터 노출은 모집 중단 우선입니다.
- 매주: 초대한 사람 중 첫 할 일을 만든 비율, 7일 내 다시 핵심 작업을 한 비율, 반복 불편, 탈락 이유. 작은 표본에서는 비율과 함께 분모를 적습니다.
- 첫 사용 정의(제안): 가입 후 24시간 안에 할 일 생성 또는 일정 생성 성공. 재방문 정의(제안): 첫 사용 후 7일 이내 다른 날짜에 같은 핵심 행동 수행.
- **현재 백오피스의 계정 수·최근 활동은 이 퍼널을 측정하는 전용 분석 시스템이 아닙니다.** 초기에는 동의한 소규모 테스터의 관찰표로 기록합니다. 자동 분석을 추가할 때는 최소 이벤트, 중복 제거, 내부 QA 제외, 개인정보 고지·동의를 먼저 설계합니다.
- 결제는 사용 가치를 검증한 뒤 별도 구현·심사합니다. 해외 사업자, 결제 공급자, 세무·환불·구독 해지 정책을 임의로 확정하지 않습니다.
