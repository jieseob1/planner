# 하위 할 일 사용법과 저장 정책

큰 할 일을 한 단계의 체크리스트로 나눕니다. 예: `로그인 오류 수정` 아래 `원인 확인`, `수정`, `회귀 테스트`.

## 사용 방법

1. **오늘의 시간 미정 목록**에서 할 일 제목을 누르거나, **시간표 블록**을 눌러 편집창을 엽니다.
2. `하위 할 일 추가`를 누르고 제목을 입력합니다. 마지막 제목에서 Enter로 다음 항목을 추가할 수 있습니다. 한국어 조합 중 Enter는 새 항목을 만들지 않습니다.
3. 체크박스로 완료/취소하고 제목을 직접 수정합니다. 화살표로 순서를 바꾸고 휴지통으로 삭제합니다. 편집창을 닫기 전 `마지막 삭제 취소`도 가능합니다.
4. 할 일 편집창에서는 `변경 저장`, 시간표 패널에서는 `하위 할 일 저장`을 누릅니다. **상단의 `서버에 저장됨`까지 확인**하세요. 편집창에서 취소/닫기를 누르기 전의 입력은 저장하지 않습니다.
5. 주간 일정의 새 할 일·할 일 수정·기존 할 일 배치에서도 같은 체크리스트를 편집합니다. 같은 할 일을 여러 시간에 배치하면 모두 동일한 하위 항목을 가리킵니다.

목록과 충분히 긴 시간 블록에는 `하위 1/3 완료`를 표시합니다. 짧은 블록에서는 공간을 지키기 위해 요약을 생략하지만, 블록을 열면 전체 항목을 편집할 수 있습니다. 제목은 500자, 상위 할 일당 최대 100개입니다. 빈 제목은 저장할 수 없습니다.

## 상위 할 일·시간·목표와의 관계

- 하위 항목을 모두 체크해도 상위 할 일이 자동 완료되지 않습니다. 반대로 상위를 완료/다시 열어도 하위 체크는 그대로입니다.
- 하위 항목은 별도 Todo나 일정이 아닙니다. 실행 시간, 목표 달성률, 기간별 완료 Todo 수를 중복해서 늘리지 않습니다.
- `시간표에서 빼기`는 체크리스트와 할 일을 남깁니다. `할 일 삭제`는 하위 항목·연결 일정·실행 기록까지 지우므로 확인창에서 범위를 보여줍니다.
- Google에서 가져온 읽기 전용 일정에는 하위 항목을 붙이지 않습니다.
- 현재 한 단계만 지원합니다. 하위 항목의 독립 일정·마감일·타이머, 다단계 트리는 구현 범위 밖입니다.

## 내부 저장

`Task.subtasks`의 `{id, title, done}` 배열을 기존 플래너 스냅샷과 같은 요청으로 저장합니다. 배열 순서가 표시 순서이며 MySQL `planner_subtask.sort_order`로 보존합니다. Flyway V13은 기존 할 일을 변경하지 않고 테이블을 추가합니다.

서버의 계정 행 잠금, strong ETag, mutation ID와 동일 트랜잭션을 사용합니다. 자식의 PK는 `(user_id, task_id, subtask_id)`이며 상위 할 일 삭제 시 FK cascade가 적용됩니다. 계정 내보내기·계획 이력에도 포함하고 계정 삭제 시 제거합니다.

기존 데이터에 `subtasks`가 없으면 빈 목록으로 읽습니다. 이미 하위 항목을 저장한 할 일을 구버전 클라이언트가 필드 없이 덮어쓰려 하면 서버가 거절하여 데이터 유실을 막습니다. 최신 화면으로 다시 연 뒤 저장해야 합니다. 최신 클라이언트의 명시적인 빈 배열 `[]`은 전체 하위 항목 삭제입니다. 충돌 시 서버/기기 데이터를 임의로 선택하지 않습니다.

## 검증

- 프론트 단위/컴포넌트: 추가·수정·완료·순서 변경·삭제 취소, 빈 제목/중복/개수 제한, IME Enter, 새로고침 복원, 부모 상태 독립, 일정만 삭제할 때 보존.
- Spring/MySQL: 생성·재조회·수정·삭제, 멱등 재요청, stale ETag 412, 구버전 필드 누락/잘못된 항목 400, 계정 격리, export, 계정 삭제 cascade.
- 격리된 MySQL 백업→복원: 완료/미완료 하위 항목 두 건의 제목·순서·상태와 기간 목표/회고의 fingerprint 일치. 운영 DB 복원 시험과는 구분합니다.
- 브라우저 전체 E2E와 공개 배포 결과는 릴리스 시점의 CI 및 [운영 배포 안내](MAIN_AUTODEPLOY.md)를 함께 확인합니다. 검증용 항목만 생성/삭제하고 실제 사용자의 할 일은 QA 목적으로 변경하지 않습니다.
